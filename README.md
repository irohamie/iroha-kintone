# iroha-kintone

NPO法人いろ葉が運用するkintoneアプリの、アプリ設定とJS/CSSカスタマイズコードを管理するリポジトリです。

## Claude Code への指示のしかた（まーくん用）

**長文を貼り付ける必要はありません。1行だけ送ってください。**

| やりたいこと | Claude Code に送る1行 |
| --- | --- |
| 最初の読み込み | `prompts/00_初回_読み込み.md の指示に従って作業してください。` |
| Phase 0：認証検証 | `prompts/01_Phase0_認証検証.md の指示に従って作業してください。` |
| Phase 1：アプリ一覧取得 | `prompts/02_Phase1_アプリ一覧.md の指示に従って作業してください。` |
| Phase 2：初回バックアップ | `prompts/03_Phase2_初回バックアップ.md の指示に従って作業してください。` |
| Phase 3：差分検知の自動化 | `prompts/04_Phase3_差分検知自動化.md の指示に従って作業してください。` |
| Phase 4：デプロイ手順の確立 | `prompts/05_Phase4_デプロイ手順確立.md の指示に従って作業してください。` |
| Phase 5：本番デプロイ運用 | `prompts/06_Phase5_本番デプロイ運用.md の指示に従って作業してください。` |
| Phase 6：対象アプリ拡大 | `prompts/07_Phase6_対象アプリ拡大.md の指示に従って作業してください。` |
| Phase 7：アプリ作成・フィールド編集 | `prompts/08_Phase7_アプリ設定管理.md の指示に従って作業してください。` |

Claude Code が該当ファイルを読み、詳細な指示を自分で受け取ります。
`CLAUDE.md` は Claude Code が毎セッション自動で読み込みます。

## 文書一覧

| ファイル | 内容 |
| --- | --- |
| `CLAUDE.md` | Claude Codeが毎セッション自動で読む永続指示 |
| `docs/01_設計図.md` | 構造・認証方式・安全性設計・デプロイゲート・禁止事項 |
| `docs/02_手順書.md` | Phase別の実作業手順 |
| `docs/03_コード生成規約.md` | コード生成のルールと検証項目 |
| `prompts/*.md` | Phase別の作業指示（Claude Codeが読む） |

## 役割分担

| 担い手 | 役割 |
| --- | --- |
| Claude Code | コードを書く、実行する、ログを読む、原因を特定する、コミット・pushする |
| GitHub Actions | 定時の自動バックアップ（人が寝ている間の実行） |
| まーくん | 方針決定、kintone画面での目視確認、デプロイ承認 |

まーくんがブラウザのF12やリモートデスクトップでログを見る必要はありません。

## フォルダ構成

```
iroha-kintone/
├── CLAUDE.md                        … Claude Codeの永続指示
├── docs/                            … 設計図・手順書・コード生成規約
├── prompts/                         … Phase別の作業指示
├── config/apps.json                 … 全アプリ一覧と有効フラグ（自動生成）
├── scripts/                         … 取得・検証・デプロイのスクリプト
├── .github/workflows/               … 自動バックアップと手動デプロイ
├── App10_利用希望調査/
│   ├── manifest.json                … ファイル順序・スコープ・MD5
│   ├── desktop/js/ desktop/css/
│   ├── mobile/js/ mobile/css/
│   └── settings/                    … フィールド・レイアウト・ビュー・一般設定
├── App42_支援計画リストビュー/
├── App207_支援計画コピー機能/
├── App219_ポータル/
├── App225_3町月次報告/
├── App227_訪問支援ダッシュボード/
├── App228_タイムカード管理/
├── App231_担当表/
├── _backup_before/                  … 変更前の退避専用（追記のみ・削除禁止）
└── _deploy_log/                     … デプロイ実行記録（追記のみ・削除禁止）
```

対象アプリは `config/apps.json` の `enabled` フラグで管理します。
現在は上記8アプリが対象で、追々すべてのアプリへ広げます。

## 安全性の要約

- **レコードデータには一切触りません。** レコードのバックアップと復元は、
  既存のGAS＋Googleドライブ方式を独立して継続します
- **kintoneには「前のバージョンに戻す」機能がありません。**
  戻せるかどうかは `_backup_before/` とGit履歴だけが頼りです
- **`PUT /k/v1/preview/app/customize.json` は全置き換えです。**
  送信内容に含めなかったファイルは黙って消えます
- **古いバックアップの削除ローテーションは行いません。** Git履歴を無期限に保持し、
  月初・年初にタグを自動付与するため、1か月前・1年前の状態にも戻れます
- デプロイは7つのゲートをすべて通過しない限り実行されません
- デプロイは自動実行しません。GitHubの承認ゲートで承認タップを必須にします
- **フィールド削除・フィールドコード変更・型変更・アクセス権変更は自動化しません。**
  データ損失や個人情報露出のリスクがあるため、kintone管理画面での手作業に限定します

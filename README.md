# iroha-kintone

NPO法人いろ葉が運用するkintoneアプリの、JS/CSSカスタマイズコードを管理するリポジトリです。

## 最初に読む文書

| 文書 | 内容 |
| --- | --- |
| `docs/01_設計図.md` | 何を、なぜ、どう作るか（構造・認証方式・安全性設計） |
| `docs/02_手順書.md` | Phase 0〜6の実作業手順（ボタン単位） |
| `docs/03_Sonnet指示テンプレート.md` | Sonnetへの指示文とコード生成規約 |
| `docs/04_ClaudeCode指示書.md` | Claude Codeに貼り付けるPhase別の指示文 |
| `CLAUDE.md` | Claude Codeが毎セッション自動で読み込む永続指示 |

Claude Codeに作業を依頼するときは、`docs/04_ClaudeCode指示書.md` のPhase別の枠内をそのままコピーして貼り付けてください。`CLAUDE.md` はClaude Codeが自動で読み込みます。

## 役割分担

| 担い手 | 役割 | kintone資格情報 |
| --- | --- | --- |
| Claude Code | コードを書く、構文検証する、コミット・pushする | 持たない |
| GitHub Actions | 書かれたコードを実行してkintoneと通信する | GitHub Secretsから取得 |
| まーくん | 実行トリガー、目視確認、デプロイ承認 | kintone管理画面で操作 |

Claude Codeはkintoneに直接通信しません。資格情報がセッション履歴に残る経路を構造的に排除するためです。

## フォルダ構成

```
iroha-kintone/
├── docs/                            … 設計図・手順書・指示テンプレート
├── config/apps.json                 … 全アプリ一覧と有効フラグ（自動生成）
├── scripts/                         … 取得・検証・デプロイのスクリプト
├── .github/workflows/               … 自動バックアップと手動デプロイ
├── App10_利用希望調査/
├── App42_支援計画リストビュー/
├── App207_支援計画コピー機能/
├── App219_ポータル/
├── App225_3町月次報告/
├── App227_訪問支援ダッシュボード/
├── App228_タイムカード管理/
├── App231_担当表/
├── _backup_before/                  … デプロイ前の退避専用（追記のみ・削除禁止）
└── _deploy_log/                     … デプロイ実行記録（追記のみ・削除禁止）
```

対象アプリは `config/apps.json` の `enabled` フラグで管理します。現在は上記8アプリが対象で、追々すべてのアプリへ広げます。

## 安全性の要約

- **レコードデータには一切触りません。** このリポジトリが扱うのはアプリ設定のJS/CSSのみです。レコードのバックアップと復元は、既存のGAS＋Googleドライブ方式を独立して継続します
- **kintoneにはJSカスタマイズの「前のバージョンに戻す」機能がありません。** 戻せるかどうかは `_backup_before/` とGit履歴だけが頼りです
- **`PUT /k/v1/preview/app/customize.json` は全置き換えです。** 送信内容に含めなかったファイルは黙って消えます
- デプロイは7つのゲート（設計図 7-5）をすべて通過しない限り実行されません
- デプロイは自動実行しません。GitHubの承認ゲートでまーくんの承認タップを必須にします

## 運用の基本ルール

1. デプロイ前に必ず現行の本番コードを `_backup_before/{日付}_{アプリフォルダ}/` へ退避してコミットする
2. テスト環境（動作テスト環境）へ反映したら、kintone画面で目視確認してから運用環境へ反映する
3. コミットメッセージは日本語で「どのアプリの、何を、なぜ変更したか」を書く
4. `_backup_before/` と `_deploy_log/` は追記専用。削除・上書きは禁止
5. アプリフォルダはリネームしない（履歴が断絶するため）
